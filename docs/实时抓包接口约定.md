## 1. 一句话说明

`sniffer.py` 只做三件事：**选定网卡抓包 → 每包转成统一 dict → 塞进有界队列**。
统计、告警、页面全部在 B、C 侧，A 不碰。离线 `parser.py` 完全不动，两条链路共用同一套 24 字段。

## 2. B 需要调用的东西

```python
from sniffer import PacketSniffer, list_ifaces, CaptureError

sniffer = PacketSniffer(iface="以太网", queue_maxsize=5000)
sniffer.start()                                  # 失败时抛 CaptureError（中文原因）

rec = sniffer.pkt_queue.get(timeout=1)           # B 的消费者：取出一个 dict
st  = sniffer.stats()                            # 采集侧计数快照（只读 dict）

sniffer.stop()                                   # 幂等，可重复调用
sniffer.running                                  # 当前是否在抓
```

- **队列对象**：`sniffer.pkt_queue`，标准 `queue.Queue`，`maxsize` 默认 5000。

### 2.1 网卡从哪来（优先级）

`PacketSniffer(iface=None)` 时按下面顺序取，第一个命中的生效：

```text
命令行 --iface  →  环境变量 SNIFFER_IFACE  →  config.json 的 capture.iface  →  自动选择（推荐网卡）
```

`config.json` 放在仓库根目录（与 `sniffer.py` 同级），只放一段 `capture`：

```json
{
  "capture": {
    "iface": "Intel(R) Wi-Fi 6E AX211 160MHz",
    "queue_maxsize": 5000,
    "bpf": null
  }
}
```

写配置不用手动编辑，直接让程序写：

```bash
python sniffer.py --save-config --iface "Intel(R) Wi-Fi 6E AX211 160MHz"
python sniffer.py --show-config      # 查当前生效配置、文件路径、环境变量
```

`sniffer.iface_source` 会告诉你这次用的是「参数 / 环境变量 / 配置文件 / 自动选择」，
页面可以把这句直接显示出来，演示时"为什么抓的是这张网卡"一目了然。

注意 `config.json` 是**本机相关**的，C 提交仓库时不要带上，避免把别人机器上的网卡名带进去。
- **消费者只能有一个**（B）。C 不读队列，只读 B 的状态快照。
- **队列满时丢新包**，不阻塞抓包线程，计入 `dropped`。

## 3. 队列里装的记录

就是 `parser.py` 的 24 字段 dict，原样输出，**只额外加一个 `capture_time`**（与 `timestamp` 同值，用来说明"这是抓包时刻"）。B 可以直接复用离线分析函数的入参形状。

```json
{"timestamp": 1764071638.123, "src_ip": "192.168.1.20", "dst_ip": "93.184.216.34",
 "src_port": 49152, "dst_port": 80, "protocol": "TCP", "length": 54, "...": "...",
 "status": "ok", "capture_time": 1764071638.123}
```

三种 `status` 的处理口径与离线一致：`ok` 正常入队；`partial` 也算入队（如 snaplen 截断、DNS 域名解析失败）；`skipped`（ARP、非 IP）**不入队**，只计数。

## 4. stats() 返回的字段（冻结，变更需通知 B、C）

| 字段 | 含义 |
| --- | --- |
| `captured` | 网卡上收到的原始包数 |
| `converted` | 转换成功并入队（含 partial） |
| `skipped` | 判定不支持而未入队（ARP/非 IP） |
| `convert_failed` | 转换异常次数（已吞掉，线程不受影响） |
| `enqueued` | 实际入队数 |
| `dropped` | 队列满而丢弃数 |
| `queue_len` / `queue_maxsize` | 当前队列长度 / 容量 |
| `elapsed_s` | 已运行秒数 |
| `last_error` / `last_error_at` | 最近一条错误文本与时间 |
| `running` / `iface` | 是否在抓 / 当前网卡 |

恒等式（自检脚本会校验）：`captured = converted + skipped + convert_failed`，
`converted = enqueued + dropped + queue_len`。

## 5. 错误提示（页面直接用这几句）

| 场景 | 提示文案 |
| --- | --- |
| 无权限 | 没有抓包权限。Windows 请以管理员身份运行并确认已安装 Npcap；Linux 请用 root 或授予 CAP_NET_RAW 能力。 |
| 缺驱动 | 缺少 libpcap/Npcap 驱动，无法实时抓包；请安装 Npcap 后重启程序（离线分析不受影响）。 |
| 网卡不存在 | 网卡「xxx」不存在。可用网卡：lo、eth0、eth1 |
| 网卡被占用/禁用 | 抓包线程未能启动。常见原因：网卡已被占用、需要管理员权限、或网卡处于禁用状态。 |

启动前会先开一个抓包 socket 立刻关掉（`preflight_capture`），把权限/驱动问题**提前**报出来，避免出现"显示在抓包、实际 0 个包"的假象。

## 6. 已知限制（演示时必须主动说）

1. 队列满即丢新包，**这只是防止内存无限增长，不等于解决了高负载丢包**；真实丢包要看 `dropped` 计数。
2. 单包转换耗时约 0.1–0.12 ms，理论上限约 8000 包/秒；超过这个速率会进入丢弃。
3. 抓包精度受网卡与 Npcap 缓冲影响，不做毫秒级时序断言。
4. 实时链路只处理 IPv4/IPv6 的 TCP/UDP/DNS 与 ICMP，ARP 等直接计为 `skipped`。

## 7. 快速验证

```bash
python sniffer.py --list                        # 列网卡：标记 / 描述 / IP
python sniffer.py --iface "以太网" --duration 10  # 真实抓包 10 秒
python sniffer.py --replay samples/normal.pcap    # 无权限也能跑通同一条链路
python scripts/check_realtime.py                  # 8 项自检
```

`list_ifaces()` 返回的每一项含 `name / description / ips / is_loopback / is_virtual / recommended`，
并按可用性排好序：**推荐**（真实网卡且有非 169.254 的 IPv4）排最前，
**虚拟**（WAN Miniport、Wi-Fi Direct、Hyper-V、VirtualBox、各层 Filter 这类抓不到流量的伪接口）标出来并排最后。
C 做下拉框时把 `recommended` 打勾项放首位，默认值取第一个 `recommended=True` 的网卡即可。

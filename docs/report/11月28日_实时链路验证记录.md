## 五、当天发现并修复的两个问题

1. **网卡列表 IP 全空、自动选择挑到 `WAN Miniport (Network Monitor)`**
   原因：用 `conf.route.route(name)` 取 IP 在 Windows 无线网卡上返回空；
   且自动选择按枚举顺序取第一个，优先选中了伪接口。
   修复：改用 `iface.ips` 取地址；`list_ifaces()` 增加 `is_virtual` / `recommended` 标记并重新排序；
   自动选择只取「推荐」项（真实网卡、有非 169.254 的 IPv4）。

2. **真实无线网卡被误判为「环回」**
   原因：用 `flags & 0x8` 判断环回，这是 POSIX `IFF_LOOPBACK` 语义，Windows 网卡标志位含义不同，
   AX211 恰好命中该位。
   修复：改为只认名字含 `loopback` 或 IP 全为 `127.` 的网卡；并在自检第 6 项加断言，防止回归。
   教训：平台相关判断（标志位、地址格式、描述名）必须在本机实测后再写进文档，不能套用 Linux 语义。

## 六、当前已知限制（演示时要主动说明）

1. 队列满即丢弃新包，仅防止内存无限增长，**不等于解决高负载丢包**；真实丢包量看 `dropped`。
2. 单包转换约 0.12 ms，理论上限约 8000 包/秒，超过即进入丢弃。
3. 抓包精度受网卡与 Npcap 缓冲影响，不做毫秒级时序断言。
4. `status=skipped`（ARP、非 IP）不进队列，只计数；`partial`（截断包、DNS 域名坏）照常入队。

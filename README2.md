局域网实时流量监控与故障诊断系统
一个面向校园网和小型局域网排查场景的网络课程进阶项目。系统抛弃了传统的“离线 PCAP 文件分析”模式，采用“被动嗅探 + 主动探测”的双引擎架构，实时监听网卡流量并主动探测关键节点，通过 Web 仪表盘直观展示网络健康状态，并给出可解释的故障线索。

当前项目定位为网络课程综合设计。它结合了底层网络嗅探（Scapy/Raw Socket）、多线程并发、主动网络探测（Socket）与 Web 全栈开发。

核心升级点（相较于基础版）
从“看录像”到“看直播”：引入 scapy.sniff() 实时监听网卡，结合多线程队列（queue.Queue），解决高并发下的丢包问题。

从“只查别人”到“自查链路”：新增主动探测模块（使用原生 socket 模块），定时 Ping 网关、测 DNS 延迟、探测外网连通性，精准定位是“节点差”还是“设备差”。

从“终端打印”到“可视化大屏”：基于 Flask 搭建本地 Web 服务，前端使用 ECharts 渲染实时的网络健康仪表盘、流量折线图和异常告警卡片。

运行与启动
因为涉及底层网卡监听和原始套接字（Raw Socket）调用，必须使用管理员/root 权限运行。

bash

python main.py --live --web

# macOS / Linux
sudo python main.py --live --web

界面功能与诊断逻辑
界面分为三大核心区块，直接回答“网络好不好”以及“为什么不好”：

1. 网络健康度总览（宏观）
顶部大屏显示当前网络健康分（绿/黄/红状态）。

节点状态栏：展示主动探测结果。如果 网关🟢通，但 DNS🔴超时，系统会直接提示：“校园网 DNS 解析异常，请检查 DNS 服务器配置”。

2. 设备实时排行（微观）
类似代理软件的节点列表，但这里列出的是局域网内的终端设备。

抓包实时统计每台设备的流量、TCP 重传率、DNS 失败次数。

诊断逻辑：如果某台设备（如 192.168.1.35）的 DNS 失败次数突发增高，系统会将其标红，并提示：“设备 192.168.1.35 DNS 解析失败率高，可能感染了恶意软件或 DNS 配置错误”。

3. 流量趋势与告警日志
每秒刷新一次的全局流量波形图。

按照规则引擎动态生成的异常卡片（如：TCP RST 比例过高、单设备流量突增）。

配置说明（config.py）
所有探测目标、阈值均集中在 config.py 中管理：

python
# 探测目标配置
PROBE_TARGETS = {
    "local_gateway": {"name": "本地网关", "target": "192.168.1.1", "type": "icmp"},
    "campus_dns": {"name": "学校DNS", "target": "10.0.0.1", "type": "dns"},
    "internet_exit": {"name": "外网出口", "target": "www.baidu.com", "type": "tcp"}
}

# 异常检测阈值配置
ALERT_THRESHOLDS = {
    "dns_fail_rate": 0.2,      # DNS 失败率超过 20% 触发告警
    "tcp_rst_rate": 0.1,       # TCP RST 比例超过 10% 触发告警
    "traffic_spike_mb": 50,    # 单设备 10 秒内流量突增 50MB 触发告警
    "node_latency_ms": 200     # 主动探测延迟超过 200ms 判定节点拥堵
}

开发与验收说明
测试与兼容性
支持在 Windows 下使用 scapy.sniff（依赖 Npcap 驱动），在 Linux/macOS 下使用原生套接字。

为了保留原有的离线分析测试，系统依然支持 python main.py --input xxx.pcap 进行纯离线分析（单线程模式，不启动 Web 界面）。

主动探测的局限与应对
跨平台 Ping：Windows 和 Linux 的 ICMP 权限不同，建议使用 subprocess 调用系统命令，或使用 ping3 库简化开发。

网卡选择：如果在多网卡环境下（如开着 VPN），需要显式指定要监听的网卡名称，否则嗅探线程可能会抓错流量。

团队分工建议
成员 A（底层与网络编程）：负责 sniffer.py 和 prober.py。实现 Scapy 实时抓包、多线程队列、Socket 原始 ICMP/DNS 探测。

成员 B（数据分析与算法）：负责 analyzer.py 和 config.py。实现流量、DNS/TCP 的异常检测逻辑，设计健康度评分算法，制定阈值。

成员 C（全栈与可视化）：负责 web/、main.py 和 reporter.py。搭建 Flask 后端，设计 ECharts 前端大屏，实现“节点状态 + 设备排行 + 告警卡片”的联动展示，以及最终的联调和数据导出。

当前已知限制
主动探测依赖外部网络环境，如果断网，系统会持续报“外网节点不可达”（这也是诊断正确的体现）。

被动嗅探受限于网卡权限，如果没配交换机镜像，只能监控本机（作为客户端）产生的局域网流量。

实时流式解析比离线解析占用更多 CPU，极端大流量下（如千兆打满）可能会有解析延迟。
